# agents — 角色指令与共用规范

开发指挥（`SKILL.md`）派角色时跑 `tools/brief.js <角色> --活 <这趟干什么> --写 <文件>`：把角色文件头上 `reads:` 点名的规范和角色本身装成一份派工书。角色只读派工书，不自己去翻别的规范。

## 六个角色

| 角色 | 文件 | 活 | 一句话 |
|---|---|---|---|
| 业务分析 | `business/business-analyst.md` | 读原料、出场景、原文选读、答问题、登词条 | 手边有原料、随时答得出原料上怎么说的人 |
| 模型师 | `model/modeler.md` | 划模块、建模、陪他按 | 照场景建模，陪人按草稿原型，接模型图上的意见 |
| 编码 | `code/coder.md` | 起草稿原型、钉契约、正式化 | 照模型写代码与产品页面，攒够了再补测试和外壳 |
| 审查 | `review/reviewer.md` | 判模型、判代码、审代码 | 只读不改，判别人写的东西 |
| 文职 | `common/editor.md` | 校对 | 只改字不改意 |
| 分身 | `common/scout.md` | 探查 | 替开发指挥查东西，只带结论回来 |

写的和查它的不合在一个角色里：模型师与审查、编码与审查。

## 共用规范

| 文件 | 管什么 | 谁带 |
|---|---|---|
| `common/discipline.md` | 写入目标、细步、发问、交稿格式 | 除分身外都带 |
| `common/wording.md` | 给人读的每一句话怎么写 | 写给人看的都带 |
| `common/project-layout.md` | 项目目录与写入权 | 要在项目里落文件的都带 |
| `business/layers.md` | 业务三层、七种语句、编号与出处 | 业务分析、模型师、审查 |
| `business/scenes.md` | 场景怎么写 | 业务分析出场景那一趟 |
| `model/shapes.md` | 模型文件的形状 | 模型师、审查 |
| `code/coding-standard.md` | 编解码规则、测试 | 编码、审查 |
