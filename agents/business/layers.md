# 业务语句：判层、种类、编号

三层是什么、为什么分层，在 [seed/principles.md](../../seed/principles.md) 第 6 条。本文是业务分析、文职、模型师落笔时用的判据。

## 业务描述的形式（文件长什么样）

陈述性语句，不写故事、步骤、角色矩阵。两类编号（能力 G、规则 R），每条带编号与 `(层-种类)` 标签，编号按点亮顺序发、永不复用。`abstraction.md` 与 `practice.md` 都按能力 / 规则分节：

```markdown
## 能力
- [G-001] (业务抽象-能力) 协调员能为参与者制定预算

## 规则
- [R-001] (业务抽象-约束) 预算总额在参与者的核定额度之内
- [R-003] (业务抽象-公式) 剩余额度 = 核定额度 − 已分配
- [R-002] (业务落地-触发) 预算被批准后，服务提供方收到通知
- [R-004] (业务落地-情形) 同一份预算可能由两位协调员先后经手
```

校验器只认以 `- [G-`、`- [R-` 开头的行（`- [U-` 是老项目里已停发的使用语句，只认不发）；语句下面缩进的依据子项（出处、批次、措辞校对记录）不是语句，工具不读。句子怎么写见 [common/wording.md](../common/wording.md)。

## 判一条话在哪层

五问，依次问；一问落到第三层就不用再问：

1. **出处是什么？** 手册、法规、领域常识 → 业务抽象。内部文档、旧系统、所有者口述 → 业务落地。只有模型师或代码这么说 → 应用行为。
2. **不用软件、也不管这家公司怎么分工，还成立吗？** 成立 → 业务抽象。不用软件成立、换家公司不成立 → 业务落地。不用软件就不存在 → 应用行为。
3. **主语是谁？** 花费、发票、参与者、案例经理、财务、政府 → 一或二。系统、字段、守卫、勾选、这一栏、录入动作 → 三。
4. **谁有资格说它错？** 会计、监管 → 一。这家公司自己 → 二。只有设计者 → 三。
5. **它引用别的编号或数目吗？**（「共五条」「见 R-144」「不进 R-189 那条等式」）引用了就不是语句，是注解，去掉或挪进依据子项。

判据一句话：**出处是手册、换一家公司还成立的，标 `业务抽象`、进 `abstraction.md`；出处是内部文档、只有这家公司这么做的，标 `业务落地`、进 `practice.md`；不用软件就不存在的，不写。** 标签和文件对不上，校验报错。分不清的写进问题清单，让开发指挥分流，不自己硬归。

两层在模型里的落点不同：**业务抽象多半落聚合**（字段、不变量、推导）；**业务落地多半落用例**（命令、执行者、编排先后）。「财务复核后才能付款」在模型里是两个命令的先后，不是聚合的不变量。

## 编号、标签、出处

- 一行一条，编号全项目唯一，按点亮顺序发，永不复用；意思没变的语句改写措辞**沿用原编号**；作废的编号不复用。
- **每条带标签 `(层-种类)`**，写在编号后面：层是 `业务抽象` 或 `业务落地`，必填；种类可省。编号字母只管身份（G 能力、R 规则），标签才管表达；改判层或种类只改括号里的字，编号不动。
- 每条标出处（手册章节、内部文档位置、裁定批次），写在语句下面缩进的依据子项里；依据子项不是语句，工具不读。
- 正文里不写数目、不引用别的编号、不写沿革和辩解。要解释就写在依据子项里。

## 七种种类

- **能力** `G-xxx`：谁能做到什么。主语是业务角色，谓语是业务动作，宾语是业务对象。它给模型一个命令或查询的锚。
- **规则** `R-xxx`，六种形状：事实、约束、公式、触发、流程、情形。正向陈述，禁令归模型。

| 种类 | 字母 | 一句判据 | 模型里落在 |
|---|---|---|---|
| 能力 | G | 谁能做到什么；说这件事有、谁做 | 命令或查询 |
| 事实 | R | 世界里有这样东西、记着这样东西；没有条件、没有算式、没有先后 | 字段，或结构性的不变量 |
| 约束 | R | 什么时候都得成立；不成立这东西就不该是这样 | 聚合的不变量，或行为的守卫加错误 |
| 公式 | R | 一个数由别的数算出来，没人手填 | 值对象或行为里的计算、领域服务 |
| 触发 | R | 一件事发生之后跟着发生另一件，没人插手 | 事件处理 |
| 流程 | R | 几个动作有先后：这个做完那个才能做，颠倒了不成立 | 后一个动作的状态守卫加错误；**前一个动作把状态挪到位的那个行为**；用例的先后 |
| 情形 | R | 业务里可能碰上的一种情况（同时、重复、成批、没成、谁看得见），软件得有个回应 | 行为的规则（状态守卫、幂等、错误） |

两层都能有全部七种。事实与情形的分别：事实陈述世界是什么样（记着什么、有什么），情形说的是可能发生什么——「两个人可能同时批」不是陈述，是边缘情况，要的是模型的回应。触发与流程的分别：触发是 A 发生之后 B 自己跟着发生；流程是 A 过了之后人才能做 B。约束与流程的分别：约束管一样东西什么时候都得成立，流程管两个动作的先后。种类是给读的人的提示，校验只拿它报警告；层和文件位置对不上、种类和字母对不上，校验报错。

**情形也是普通的 R**（同时、重复、成批与部分失败、没成了业务上怎么处置、谁在什么时候能看见）：只写情况，**不写软件怎么回应**——只算一次、记先到的、幂等、锁、批量语义、查询的范围，那是第三层，归模型师，写在元素规则里一句「本步这么做」。这五种情况是认出这一种语句的判据，不是每段要拿去问的清单。原来单独一类的使用语句 `U-xxx` 已停发：它把事实和回答缝在一句里，既不像抽象业务也不像公司流程。
