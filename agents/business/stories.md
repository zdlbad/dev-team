# 故事与关系：业务里一段事怎么走、一份事实怎么推出另一份

*业务分析写，工作台「故事」「关系」两页照它画，人在页上按「定下」。模型师整理聚合设计时拿它们当出处。*

语句一条一条说规矩，说不出整段事怎么连着走、几份事实之间谁推出谁。故事和关系补的就是这两样：故事讲先后，关系讲推出。两样都只写业务里真有的事，**不提聚合、字段、系统**；聚合设计的 `refs` 指回它们（「<故事名> #<步骤>」「<关系名> #<线>」）。

## 故事：`business/故事/<nn>-<故事名>.json`

业务里真实发生的一段事，跨着好几方，不按聚合切。拿一个举例的人和她的日子从头走到尾：谁对谁、做了什么、哪天、期限多久、手册哪一节。

```jsonc
{ "title": "从入册到退出",
  "summary": "拿一个举例的人和日子说这段事，一两句",
  "participants": [ { "id": "elder", "title": "老人" } ],          // 一方一道，钉在页面左边
  "phases": [ { "id": "intake", "title": "入册" } ],                  // 段名横在顶上
  "branches?": [ { "title": "进来的路", "items": [ { "key": "①", "title": "新评估", "detail?": "", "source?": "", "shown?": true } ] } ],
  "steps": [ { "id": "1", "phase": "intake", "by": "elder", "to?": "服务方", "title": "交来决定通知书",
               "date?": "3 月 4 日", "due?": "28 天内", "every?": "每季", "source?": "§6.2 行 812",
               "pending?": "问的是什么、在哪里问", "traces?": ["R-012"] } ],
  "loops?": [ { "from": "7", "to": "5", "label": "每季重来一遍" } ],
  "questions": [] }
```

- **参与方用原料里的角色**：手册里叫什么就叫什么（老人、服务方、评估机构、政府），不写这家公司的名字，也不按公司之间怎么分包拆成几道。故事讲的是这门业务里谁对谁做事，换一家公司照样这么走。
- **一步一件事**：谁做（`by`）、交给谁（`to`）、做了什么（`title`，动宾短语）。步骤按先后排，编号 `1`、`2`、`2a`，发了不改。
- **例子里的日子写在 `date`**，期限写在 `due`，按月按季打转的写 `every`，绕回去的那一段写进 `loops`。
- **进来、出去不止一条路的**，写成 `branches` 摆在头尾，图上走的那条标 `shown`。
- **原料没说、要人定的**，写在那一步的 `pending`，同时照「答问题」第 2 条发问；人定了，把 `pending` 去掉、把答案写进那一步。
- 一步立成了语句的，`traces` 挂编号。
- **一篇讲一件事**（开始服务之前怎么排队签约、开始服务那几天、在册以后每季每月怎么转、退出），一屏走得完；比一个场景大，场景是故事里的一小段。一件事接着另一件的，拆成几篇，编号排出先后，`summary` 末尾写明从哪一篇接来、接着哪一篇；举例的人和日子几篇用同一套。

## 关系：`business/关系/<nn>-<关系名>.json`

一份事实怎么推出另一份，没有先后：原料里的那张纸推出哪几样东西，再被政府定死的清单缩小到哪里。时序讲不清、要画成图才看得出谁靠谁的，写成关系。

```jsonc
{ "title": "每个账户能买什么",
  "summary": "从哪几张纸推出什么，一两句",
  "note?": "图底下补一段：例外、不走这张图的情形",
  "nodes": [ { "id": "notice", "title": "决定通知书", "sub?": "政府寄来", "kind": "paper",
               "facts?": [ { "name": "级别", "text": "第 5 级" } ], "source?": "§6.1" } ],
  "edges": [ { "id": "1", "from": "notice", "to": "account", "kind": "derive", "label?": "批了持续服务",
               "text?": "这条线说的是什么，一句话", "source?": "§6.3", "traces?": [] } ],
  "examples?": [ { "id": "xin", "title": "老人辛", "note?": "", "nodes": { "notice": "第 5 级" }, "edges": ["1"] } ],
  "questions": [] }
```

- **节点分三种**：`paper` 原料里的纸（通知书、计划）、`derived` 从纸推出来的、`fixed` 政府定死的清单。
- **线分三种**：`derive` 推出、`also` 也能、`narrow` 再缩小；`label` 写线上的条件，几个字；`text` 写这条线说的是什么。线有编号，发了不改。
- **拿一个人看**：`examples` 里列她走过的节点和线、节点旁边写她的数，页面上只亮这几条。

## 定下

人在页面上按「定下」，页面写 `confirmed`（时间与内容指纹）；之后内容再改，页面显示「改过」，等人重按。你改人已经定下的故事或关系，交回里说一句改了哪几步、哪几条线，开发指挥转给人重按。
