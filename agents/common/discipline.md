# 纪律（每个角色都带）

## 开发指挥启动你时附上的

```
项目目录：<绝对路径>        dev-team 目录：<绝对路径>（下称 $DEV_TEAM）
切片：<id>（标题；场景；挂着的语句）
任务：<一句话，这一趟做什么、做到哪停>
```

## 只写自己的写入目标

每个工件只有一个写入角色，表在 `common/project-layout.md`。别人的东西不对，写进问题清单，不动手改。

## 一条 git 命令都不许跑

提交、切分支、回退都是开发指挥的事。

## 不造词，不猜业务

名字用词汇表里的；词汇表没有的，提给业务分析。原料和裁定都没说的事不猜，问人。

## 边做边写细步

每做完一个小动作就写一句：

```
node $DEV_TEAM/tools/scene.js <项目> progress <你的角色名> "<做了什么>"
```

具体到名字、从什么到什么，例如「新建错误 InvalidExpense：金额不是正数时抛」「在翻手册 §13.7 找管理费的封顶」。

- 接活先写一句：这一趟打算动哪几个文件。
- 每改完一组文件写一句，不攒到最后。
- 一件事做得久，每过几分钟报一句现在到哪儿。
- 一句就够。**一句都没有就是漏了**：人开着看板看后台，没写他就不知道在干什么。

## 遇到要人裁的事当场发问

```
node $DEV_TEAM/tools/scene.js <项目> ask "<问题>" --who <你的角色名> --doing "<在做什么>" --context "<牵涉谁、哪个文件、哪一步>" --options "甲：…|乙：…" --lean "<你偏向哪个>" --confidence 高|中|低
```

五件事说全：在做什么、上下文、问题、两到四个答案、你偏向哪个和信心高低。说人话，落到具体的人和事上。问完照它打印出来的那句办：

- **逐个**（人在电脑前）：停下来，交回开发指挥，等答复送回来再接着做。
- **问卷**（人不在）：照你偏向的先做下去，写一句细步说明这里是按偏向做的；答复跟你偏向不一样的，会叫你回来返工。

分得清什么该问：口径、范围、要不要拦、叫什么名字是人的；怎么落成代码、写在哪个文件是你的。**分岔不问**：先走主线，守卫、重复、异常等人在页面上按出来。

## 交稿

最后一段固定为：

```
## 产出
- <写了、改了哪些文件，一行一个>

## 问题清单
- <要交代给开发指挥的事，一行一个；没有写「无」>
```

先说发生了什么，再给编号。要人裁的走 `scene ask`，不只写进问题清单。
