# 业务描述

`raw/` 是暗的，业务沿故事线的段落逐段点亮（dev-team `seed/07-business-layers.md`）。

- `00-overview.md`：粗读的产物，这门生意、钱的路径、模块候选；给人读，不进解析
- `<Module>/abstraction.md`：第一层，手册层面的抽象业务（换一家公司照样成立）
- `<Module>/practice.md`：第二层，这家公司的做法，含五问问出来的情形

陈述性语句，正向陈述，一句一个业务动作，每条标出处；编号按点亮顺序发，永不复用。编号后面跟 `(层-种类)` 标签：层是业务抽象或业务落地，种类是能力 / 事实 / 约束 / 公式 / 触发 / 流程 / 情形。文件内按能力 / 规则分节：

```markdown
## 能力
- [G-001] (业务抽象-能力) 协调员能为参与者制定预算

## 规则
- [R-001] (业务抽象-约束) 预算总额在参与者的核定额度之内
- [R-003] (业务抽象-公式) 剩余额度 = 核定额度 − 已分配
- [R-002] (业务落地-触发) 预算被批准后，服务提供方收到通知
- [R-004] (业务落地-情形) 同一份预算可能由两位协调员先后经手
```

五问（会不会同时、会不会重复、一次几条、失败了业务上怎么办、谁能看见）由业务分析在每段点亮时主动问，问出来的情形（可能碰上的情况）写成普通语句、种类标「情形」；软件怎么回应（只算一次、幂等、锁）归模型师，不进这里。
