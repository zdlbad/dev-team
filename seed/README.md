# dev-team — 种子：核心思想

三份，只记思想，不记做法。做法（角色怎么干、文件长什么样、代码怎么写、校验查什么、句子怎么写）全在 `agents/`，按关注点分文件夹，派角色时由 `tools/brief.js` 装配；开发指挥的做法在 `SKILL.md`。**角色运行时不读这里。**

| 文档 | 内容 |
|---|---|
| [principles.md](principles.md) | 骨架十二条：一个源头、两份真相、一把尺子；底层三元素；可编码 / 可解码；两层模型；放置规则；两速决策；每个工件只有一个写入角色；Agent 提议人决定；命名贯通；结构化真相；切片是步伐 |
| [slices.md](slices.md) | 三阶段；阶段一的两种速度；四种切片；**开发范围怎么切**（故事线 → 段落 = 切片 → 模块职责 = PR → 聚合改动 = commit；段落判据；分支按轮次；门禁不拿先例软化；改说法切片的门禁）；差异回流 |
| [layers.md](layers.md) | **业务分三层**（业务抽象 / 业务落地 / 应用行为）与为什么分；五问问的是情形、回答归模型师；**点亮**（raw 是暗的，沿故事线 → 段落 → 模块 → 聚合 → 行为逐级点亮；故事写在语句之前；人先读原文） |

## 改 dev-team 自己时

- **底层思路变了**（多一层、少一种切片、写入权换人、放置规则变）：**先改这里**，再从这里出发改 `agents/` 与 `SKILL.md`，一件事只写在一处。
- **只是做法变了**（一个角色多一步、一条句子怎么写、一张表加一行）：直接改 `agents/` 里那一份，这里不动。
- 谁在什么时候出过什么事，写在那条规矩旁边一句「由来」，不另立文件。
