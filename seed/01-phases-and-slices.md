# 01 — 阶段与切片

*dev-team 种子文档。上位文档：[00-principles.md](00-principles.md)。业务分几层、怎么点亮见 [07-business-layers.md](07-business-layers.md)。*

## 三个阶段

| 阶段 | 方向 | 角色 | 产出 |
|---|---|---|---|
| 一 | 业务 → 模型 | 业务分析、讲解、模型师 | 全景与模块候选、按段落点亮的业务描述、词汇表、模块划分、两层模型 |
| 二 | 模型 → 代码 | 原型、接口、编码 | 代码（模型的实现，依编码规范） |
| 三 | 校验 | 模型校验、pre-pr 审查 | 报告 |

开发指挥贯穿三个阶段（见 05）。阶段一是完整的建模阶段，不考虑代码；模型带着可编码的形态只是 DDD 模式的副产品。阶段二是模型的实现，编码规范在此生效。阶段三分两段：设计模型对业务描述；代码解码出的实际模型对设计模型。两段合起来即代码对业务。

## 阶段一的内部结构

```
粗读 raw ──────────────▶ 全景、模块候选（主题）、词汇表种子；不写编号语句
   │
   ▼ 战略设计（一次，可回流）▶ 模块划分 + 模块级模型的「职责 / 关系」
   │
   ▼ 故事线 → 段落 ────────▶ 这一段点亮的事实（07），归模块
   │
   ▼ 战术・边界 ──────────▶ 这一段触及的聚合清单（名字、根、id 引用）
   ▼ 战术・内容 ──────────▶ 聚合级模型（实体、值对象、行为、事件、错误）+ 模块级的「领域服务」
   ▼ 战术・编排 ──────────▶ 模块级模型的「用例」
```

| 步骤 | 写入 | 速度 | 门禁 |
|---|---|---|---|
| 粗读 | 全景、模块候选、词汇表种子 | 一次 | 人读过 |
| 战略设计 | 模块划分；模块级模型的职责 / 关系 | 慢 | 单独确认；段落点亮时修正走正式回流 |
| 战术・边界 | 模块级模型的聚合清单 | 慢 | 单独确认 |
| 战术・内容 | 聚合级模型；模块级的领域服务 | 快 | 随段落确认 |
| 战术・编排 | 模块级模型的用例 | 快 | 随段落确认 |

模块级模型里混着两种速度：聚合清单是慢的，用例编排是快的。门禁按速度分开，不按文件分开。

## 切片

切片是迭代的步伐。四种：

- **段落切片**（默认）：一段故事，单一业务意图。点亮 → 理解一致 → 五问 → 最少模型 → 裁定 → 模型确认 → 编码计划 → 原型 → 校验 ② → 审查 → 人按。
- **实现切片**：若干条已在原型上走通的段落换上生产外壳。契约 → 计划 → 外壳 → 校验 ② → 审查 → 合并。
- **改说法切片**（`refactor`）：只改说法或结构、业务行为一个字不变。不走故事、不走裁定卡、不算施工单；门禁见下。
- **修改切片**（`change`，编号 m-xxx）：已走通的段落上，试原型、审阅或裁定点出的**一件事**——业务行为或模型结构要改，不是改说法。先记成候选、不当场改；当前段落收口后挑一件开。周期见下。

战略设计不是切片，是一次单独门禁。

### 开发范围怎么切

> 由来：2026-09-11，项目所有者在验收项目跑到第十九批裁定时说「开发的范围太大了……人类根本消化不掉」：一处堆了七道守卫、关键逻辑 2,585 字；施工单重算三次人一次都没确认；另一条走完整条链的切片施工单 88 步。两个原因并列：**一次想的东西太多**（药是切小，本节）；**裁定答在错的层上**（药是分层，07）。

**业务和模型都按段落点亮，一次只想一段。** 层级如下，业务与模型沿同一条层级往下：

| 层 | 一个单位是什么 | 业务这边 | 模型 / 代码这边 | 产出 |
|---|---|---|---|---|
| **故事线** | 完整的故事链，跑通一个多角色多模块的场景 | 从 raw 选一条线：人物、起点、终点、碰哪几个模块 | 定跨哪几个模块 | 若干段落 + 一份短索引（先后与一句衔接） |
| **段落** | **一个最小业务动作**，单一业务意图；至多两个模块，一个模块自己也算 | 点亮这一段用到的事实，归模块 | 这一段的命令与用例 | **= 一个开发切片** |
| **模块的职责** | 一个模块的一个职责 | 事实归哪个模块 | 模块内几个聚合协作 | **= 一个 PR** |
| **聚合的改动** | 一个聚合改一次 | 事实落哪个聚合、行为守哪条 | 字段、不变量、行为 | **= 一个 commit** |

段落是模块的演绎，反映落在模块上的事实。事实、段落、职责都定义一次、引用多次，不登记「谁用了我」。

**一个段落的判据**（同时满足）：

1. **单一业务意图**：切片记录里写明一句话（`intent`）。写不出一句话，就是不止一个意图。
2. **标题就是那个动作**：「上传发票源文件」「从发票录入花费」「案例经理审批花费」。哪张纸、哪一笔是例子，写在前情与步骤里，不进标题。
3. **最多两个模块**，这是上限不是门槛。三个就得再切；一个模块自己也合格，不必为了凑两个把下一段拖进来。
4. 与相邻段落的衔接**只写一句**（故事文件的 `leadsTo`），不在本段展开。

一个 **PR** = 一个模块的一个职责；施工单里属于同一个 PR 的步骤，模块必须相同。一次 **commit** = 一个聚合改一次；一步同时动两个聚合就拆成两步。

**分支按轮次进来。** 第一轮只走主线；每条分支（守卫、异常、怪事）标明属于哪一轮，由后一轮的段落带进代码。**守卫也是分支**，七道守卫一次落地就是违反这一条。一段的第一轮做完就进下一段，不在本段续深。

**施工单的一步是增量，不是整建。** 对已存在的文件，一步写成「给 `Expense` 加 `takeFromLine` 这一个行为」，不是「建 `Expense` 聚合根，含十二条行为」。

**改说法切片的门禁**，两条，第二条必须可证明：

1. 测试照旧全绿，通过数与改前一模一样，断言的业务事实（金额、GST、余额、行数、错误种类）一个都不动；跟着改名走的状态标签不算业务事实。
2. 把改名套在「改前」的解码结果上，与「改后」的解码结果逐字节比，必须一字不差。不写成「代码跟模型 0 差异」，因为模型常跑在代码前面，那时 0 差异达不到，而达不到的原因与改名无关。

### 段落切片的周期

- **定线与分段**（开发指挥 + 人）：从 raw 选故事线，切段落，排先后，第一段永远是最贴近日常、点亮事实最少的那段；每段定第一轮只走哪条主线。
- **写故事**（讲解）：一个人物、按日期排的步骤、具体金额，每步标它需要哪条业务（`needs`，人话）。故事写在语句之前。
- **点亮与五问**（业务分析，一趟）：按步骤的 `needs` 回 raw 找，写成正向陈述句、标出处、发编号、归模块，回填步骤的 `traces`；同一趟把这一段走到的每个动作过五问（会不会同时、会不会重复、一次几条、失败了业务上怎么办、谁能看见），问出来的公司事实写成语句并登记（`story usage propose`）。交稿前按 07 第三节自检措辞。
- **最少模型**（模型师，人走故事之前）：只建走通这一段所需的最少模型；每一步填 `walk`；业务逻辑的选择列成裁定卡，应用行为不列。人还没走故事，他走时质疑或裁定不同再回流。
- **总校**（文职，一趟）：本段新语句与新建、改动的模型文字只改字不改意；改完写整句对照、跑 `validate --重新定基` 把裁决接回来；`slice proofread` 记一笔。文职是最后一个动文字的人，排在校验角色填判断之前。
- **校验 ① 机械检查**（开发指挥自己跑）→ **出题**（讲解：预测再揭晓，把卡改成人话）。
- **人一坐**（走故事页）：逐步读、逐条确认语句、同意或质疑（理解一致）；确认五问补出的语句；预测；过裁定卡。四件一次坐完。→ 开发指挥写回、分流 → 回流模型师 → 校验角色填判断 → **审模型**（人）：审完干净直接算模型确认，不再单点一次。
  > 由来：2026-09-14 第八十九批。s-002 那一段派了 14 趟角色、人坐了 9 次，同一段故事人在故事页坐三回、文职单独跑三趟。项目所有者：「来回太多了」，选甲。
- **编码计划**：模型确认后、写码之前，开发指挥从模型算出这次要动哪些代码文件、按什么顺序；写码角色在每一步下面补关键逻辑；**人确认后才开写**，每完成一步登记一次。原型与外壳两次都有计划、都要人看。
- **原型**：按计划把这一段变成能按的东西——领域层与应用层按编码规范写（这就是最终代码），仓储与端口用内存适配器；先跑本故事线前面的段落，再跑本段；校验 ② 干净后 **pre-pr 审查**（A / B / D / S）；然后人打开页面按故事走，试连点、同时、成批。**每一段都反映在原型上**，原型是操作逻辑的验收，也是代码的第一层。

### 实现切片

指定若干条已在原型上走通的段落（`--implements`），范围从它们走过的聚合与用例推出。先由**接口角色**把外壳的契约钉死（`contracts/`：每个命令 / 查询的 HTTP 入口、每个聚合的表结构、每个模块的错误 → 状态码；字段名沿用模型，类型不确定就问人，没问过的与故意推迟的分开标），人确认；再出外壳的编码计划，人确认；编码角色只补生产的外壳（数据库、消息、接口），领域代码不重写；校验 ② 仍须 0 差异；pre-pr 审查查 C / E / F / S。几段攒够了一起上。编码中发现模型要改的，回到那一段的切片。

### 修改切片

> 由来：2026-09-14，验收项目第八十三～八十五批（拨款出处要核、语句全部重写、三条规则抽成领域服务）都没有切片记录，挂在 s-001 与 s-002 底下当「回流」——s-001 收了两次口，s-002 的模型确认、代码、计划重算了三次。项目所有者：「横切回流也是一种切片……颗粒度彻底失去了用处，现在完全是靠段落除法，随时回头，讨论范围既是修改范围了。」（第八十六批）

- **来源只有一个**：已走通的段落上，试原型页、审阅页或裁定点出的一件事。段落还没收口时发现的、不超出本段范围的，仍按「切片内的轻量修正」当场改。
- **候选先记，不当场改**：人在审阅页、试原型页上点出的事，开发指挥记进 `slices/_candidates.json`（`slice candidate add`：一句话改什么、谁在哪儿点出的、动到哪几段），当前段落照走。收口后人从候选里挑一件开成修改切片（`slice candidate open`）；**一个修改切片只改一件事**。不做的标明为什么（`drop`）。
- **周期**：业务语句要改的先改（业务分析、文职）→ 模型师改模型 → 文职 → 校验 ① → 人审模型 → 编码计划（只列这一件事动到的文件）→ 原型补关键逻辑 → 人确认 → 原型改代码与测试 → 校验 ② → pre-pr（A / B / D / S）→ 人在原型上重走它动到的段落 → 收口。
- **记录**：切片记录 `kind: change`、`origin`（来源）、`touches`（动到哪几段）、`candidate`（从第几号候选开的）。裁定照记进裁定文件；被动到的段落不重开、不改它们的阶段。工作台「切片」页列段落 / 修改 / 候选三栏。

### 差异回流

| 发现 | 回到 |
|---|---|
| 代码未按模型实现 | 阶段二 |
| 模型本身不对 | 阶段一（战术） |
| 业务描述有缺口或矛盾 | 阶段一（点亮那一段） |
| 触及模块划分或聚合边界 | 阶段一（战略 / 战术・边界），单独门禁 |

### 切片内的轻量修正

编码中发现的、**不超出本切片范围**的模型修正：模型师改，人看差异即可，不重跑校验 ①。超出范围（尤其触及边界）才升级为正式回流。段落已收口之后才发现的，不走这条：记候选、开修改切片。

## 角色与写入权

| 角色 | 阶段 | 唯一写入目标 | 不得写 |
|---|---|---|---|
| 业务分析 | 一 | `business/00-overview.md`、`business/<Module>/abstraction.md`、`business/<Module>/practice.md`（含五问问出来的公司事实）、词汇表 | 模型、代码、故事 |
| 讲解 | 一（衔接业务到模型） | 故事（人物、步骤、`needs`、题目、缺口）、导读 | 业务描述、词汇表、模型 |
| 模型师 | 一 | 模块划分、两层模型；故事的 `walk` 与 `choices` | 业务描述（提交问题）、词汇表（提交新词）、代码 |
| 文职 | 一（点亮之后、模型师交稿之后，各校一遍） | 业务语句的正文与模型元素给人读的文字——只改字不改意，直切核心概念 | 编号、标签、追溯、结构、故事、题目、卡、词汇表、代码 |
| 原型 | 一→二 | 故事的领域层、应用层、内存适配器、组合根、原型入口、领域与用例测试；故事的 `walk.input`；计划的关键逻辑与完成记录 | 模型（报告不一致）、词汇表、契约 |
| 接口 | 二（实现切片开头） | 契约 `contracts/` | 代码、模型、业务描述 |
| 编码 | 二 | 生产外壳与外壳测试；计划的关键逻辑与完成记录 | 模型（报告不一致）、词汇表、契约（报给接口角色）、领域层与应用层（回到那一段） |
| 模型校验 | 三 | 校验报告 | 一切工件 |
| pre-pr 审查 | 三 | 审查报告 | 一切工件 |
| 解读 | 零 | `raw/legacy-reading.md`、词汇表的别名、模型草稿、解读说明 | 代码、`business/` |
| 开发指挥 | 贯穿 | 切片记录、候选修改清单、故事线索引、编码计划的骨架、模型文件的 `decisions[]`、裁定文件、五问补出的编号登记 | 业务描述、模型、代码、契约、报告 |

人在每个阶段末拍板，并可直接编辑任何工件。

## 还没落进工具的

- 故事步骤的 `needs` 与「待点亮」状态在故事页上显示。
- 「这条故事是不是跨了段落」没有机器判据；暂时靠人在故事页上看。
- 故事线那一份短索引（段落先后、一句衔接、每段到第几轮、状态）的工具与页面。
- 施工单按 PR 分组；施工单的一步改成增量而不是整建。
- 节奏门禁的两道拦截：一段施工单的步数、一步关键逻辑的字数。
- 原型「先跑本故事线前面的段落」要读故事线索引。
- 分支标轮次，第一轮只走主线。
