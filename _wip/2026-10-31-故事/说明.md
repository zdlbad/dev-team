# 故事页小样（2026-10-31，定下）

项目所有者 10-31 说的：一门业务里故事很多，不需要每个细节都照顾到，故事页只关注最最主要的业务（老人注册：从通知书和支持计划到合同到建档案；老人接受服务到服务上报）；故事可以跨模块，不要太多细节，关键步骤仍以文字辅助说明；形式用时序图。小样 `小样.html` 当天看过，说「故事的小样可以」。画法写进了 `ui/guideline.md`「故事页：时序图」。

## 跟现在的故事页差在哪

- 现在 `business/故事/` 五篇是按状态一段段切的（待评估 → 未签约 → 已签约 → 已到位 → 在册 → 退出），一篇一屏，按参与方分道、时间从左往右，带上一步/下一步、拖、岔路芯片。
- 定下的：**一篇讲一条主线**，可以把现在的几篇并成一篇（老人注册 = 01 + 02），步骤粗一点；时序图从上往下；状态改成左边的虚框括住几步；岔路（branches）、loops 不画了，要说的写进关键步的 note。

## 数据形状改动（真做时 `business/故事/<nn>-<故事名>.json`）

```jsonc
{ "title": "老人注册：从通知书到签协议、建档案",
  "summary": "一两句，举例的人和日子",
  "parties": [ { "id": "old", "title": "老人", "sub?": "和她登记的支持人" } ],          // 原 participants；sub 原 note
  "states": [ { "id": "s1", "title": "待评估", "from": "1", "to": "3" } ],              // 原 phases；括住哪几步直接写 from/to
  "steps": [ { "id": "3", "from": "gov", "to": "old", "title": "评估批了持续服务，发决定通知书和支持计划",
               "date?": "02/03/2026", "due?": "", "data?": ["决定通知书", "支持计划"],  // data：这一步交出、记下的数据，名字对概念页的
               "note?": "关键一步的说明，一两句", "source?": "", "traces?": ["R-050"], "pending?": "" } ],
  "questions": [], "confirmed?": {} }
```

`by`/`to` 改成 `from`/`to`，都是 parties 的 id；自己对自己的 `from === to`。`branches`、`loops`、`every` 不要了。
